# Changelog

Todos los cambios notables a este proyecto se documentan aquí.

El formato sigue [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) y este proyecto adhiere a [SemVer](https://semver.org/spec/v2.0.0.html).

Cada entrada se documenta en **español** y **english**.

## [Unreleased]

### Added
- ES: **cambio observable** — `nz-mcp init` y `nz-mcp add-profile <nombre>` abren un **asistente de pantalla completa** con los ocho campos a la vez. Te mueves con Tab, corriges cualquier campo sin rehacer los que van detrás, la pantalla dice qué falta y explica el campo seleccionado mientras lo escribes. Es la única excepción al ADR 0005 y está acotada a este comando por el ADR 0028; los otros nueve (`test-connection`, `list-profiles`, `switch-profile`, `edit-profile`, `remove-profile`, `doctor`, `probe-catalog`, `version` y `serve`) siguen siendo texto puro (issue #221).
- EN: **observable change** — `nz-mcp init` and `nz-mcp add-profile <name>` open a **full-screen wizard** with all eight fields at once. Tab moves between them, any field can be corrected without redoing the ones after it, the screen says what is still missing and explains the field you are on while you type it. It is the single exception to ADR 0005, scoped to this one command by ADR 0028; the other nine (`test-connection`, `list-profiles`, `switch-profile`, `edit-profile`, `remove-profile`, `doctor`, `probe-catalog`, `version` and `serve`) stay plain text (issue #221).
- ES: **la degradación es parte de la funcionalidad, no un plan B.** Si el entorno no puede con la pantalla, el comando cae **solo y sin avisar** a las mismas ocho preguntas encadenadas de siempre y configura exactamente igual: mismo `profiles.toml`, misma password en el keyring, mismo perfil activo. Siete disparadores: salida o entrada redirigida o en tubería (CI incluido), `TERM=dumb`, un `TERM` vacío, sin definir o que la base terminfo no reconoce en POSIX —habitual dentro de contenedores y en algunos multiplexores por SSH—, consola de Windows sin secuencias VT, ventana por debajo de 60x21 al arrancar, `NZ_MCP_NO_TUI=1`, y —esto es nuevo respecto al ADR— **achicar la ventana por debajo del mínimo a mitad de sesión**, que es lo habitual por SSH. En ese último caso lo que ya habías escrito se conserva y pasa a ser el valor por defecto de cada pregunta, incluida la password si ya la habías dado (issues #221, #168).
- EN: **degradation is part of the feature, not a plan B.** When the environment cannot host the screen, the command falls back **on its own and without a warning** to the same eight chained questions as always and configures exactly the same thing: same `profiles.toml`, same keyring password, same active profile. Seven triggers: input or output redirected or piped (CI included), `TERM=dumb`, a `TERM` that is empty, unset or unknown to the terminfo database on POSIX — routine inside containers and in some multiplexed SSH sessions —, a Windows console without VT sequences, a window below 60x21 at start-up, `NZ_MCP_NO_TUI=1`, and — new with respect to the ADR — **shrinking the window below the minimum mid-session**, which is routine over SSH. In that last case whatever was typed is kept and becomes the default of each question, credential included when it had already been given (issues #221, #168).
- ES: **la password nunca entra en la pantalla.** No hay campo de password en el modelo de estado del asistente: solo un booleano *"definida / sin definir"*. Se pide fuera del árbol de widgets, con la aplicación suspendida y el eco apagado, y viaja envuelta en `Secret` como en el resto del proyecto. El motivo está medido en el ADR 0029: un campo de texto de `textual` reconstruye su valor al teclear, así que un `Secret` no sobrevive a la primera pulsación. Lo vigila un chequeo automatizado, no una regla escrita (issue #221).
- EN: **the credential never enters the screen.** The wizard's state model has no password field: only a *"set / not set"* boolean. It is asked for outside the widget tree, with the application suspended and the echo off, and travels wrapped in `Secret` like everywhere else in the project. The reason is measured in ADR 0029: a `textual` input rebuilds its value as you type, so a `Secret` does not survive the first keystroke. An automated check enforces it, not a written rule (issue #221).
- ES: nuevo test de contrato `test_wizard_credential_guardrail.py`, en la línea del detector AST que confina `rich`, pero **por lista blanca y no por lista negra**. Enumera toda la superficie de `src/nz_mcp/wizard/` —los módulos que puede importar, cada parámetro con su tipo, cada atributo de la aplicación, cada campo de `DraftFields`, cada nombre a nivel de módulo y las expresiones que pueden llegar a un widget— y rompe el CI ante cualquier hueco nuevo. Una lista negra de nombres sospechosos se esquiva renombrando la credencial; una lista blanca de huecos no, porque no quedan huecos libres. Veinte violaciones inyectadas comprueban que el detector detecta, y un segundo test arranca la aplicación de verdad, recorre el árbol de widgets terminado y busca el valor —que es lo que la regresión del `Secret` del PR #193 no tenía (issue #221).
- EN: new contract test `test_wizard_credential_guardrail.py`, in the spirit of the AST detector that confines `rich`, but **by allowlist rather than blacklist**. It enumerates the entire surface of `src/nz_mcp/wizard/` — which modules it may import, every parameter with its type, every application attribute, every `DraftFields` field, every module-level name, and the expressions allowed to reach a widget — and fails CI on any new slot. A blacklist of suspicious names is walked past by renaming the credential; an allowlist of slots is not, because there are no free slots left. Twenty injected violations prove the detector detects, and a second test starts the real application, walks the finished widget tree and searches for the value — which is what the `Secret` regression of PR #193 did not have (issue #221).
- ES: tests de la interfaz con `Pilot`, sin terminal y sin dependencias de desarrollo nuevas: teclear, tabular, volver a un campo anterior sin perder los siguientes, redimensionar la ventana en vivo y comprobar que en la ventana mínima no se cae nada fuera de pantalla. Y un test por cada uno de los seis disparadores de degradación de arranque, cada uno desde una puerta completamente abierta, para que ninguno pase en verde porque saltó otro (issue #221).
- EN: interface tests driven by `Pilot`, with no terminal and no new development dependencies: typing, tabbing, going back to an earlier field without losing the later ones, resizing the window live, and checking that nothing falls off the screen at the minimum size. Plus one test per start-up degradation trigger, each starting from a fully open gate so that none of them passes green because a different one fired (issue #221).
- ES: nuevas claves i18n ES/EN para el asistente de pantalla completa: las ocho etiquetas de campo (`CLI.WIZARD_FIELD_*`), el título, la línea de teclas, el estado de la password, *"falta por rellenar"*, *"listo"*, el aviso de degradación por tamaño y `CLI.WIZARD_PORT_INVALID`. Las explicaciones largas de cada concepto **no se duplican**: son las mismas `CLI.WIZARD_*_EXPLAIN` que ya imprimen las preguntas encadenadas (issue #221).
- EN: new ES/EN i18n keys for the full-screen wizard: the eight field labels (`CLI.WIZARD_FIELD_*`), the title, the key hints line, the credential state, *"still missing"*, *"ready"*, the size-degradation notice and `CLI.WIZARD_PORT_INVALID`. The long explanations of each concept are **not duplicated**: they are the same `CLI.WIZARD_*_EXPLAIN` entries the chained questions already print (issue #221).

### Changed
- ES: **dependencia nueva** — se declara `textual>=8.2,<9` (ADR 0029), confinada a `src/nz_mcp/wizard/` y usada solo por el asistente. Coste real medido: **+4 paquetes y ≈3,8 MB** en disco, para un solo comando. El tope es de un major porque `textual` publicó ocho en catorce meses. El detector AST del test de contrato pasa de un conjunto de módulos confinados a un **mapa módulo → destino**: `rich` sigue viviendo solo en `cli_output.py`, `textual` solo en `wizard/`, y ninguno de los dos puede entrar en la casa del otro (issue #221).
- EN: **new dependency** — `textual>=8.2,<9` is declared (ADR 0029), confined to `src/nz_mcp/wizard/` and used only by the wizard. Measured real cost: **+4 packages and ≈3.8 MB** on disk, for a single command. The cap is one major because `textual` shipped eight of them in fourteen months. The AST detector in the contract test moves from a set of confined modules to a **module → home map**: `rich` still lives only in `cli_output.py`, `textual` only in `wizard/`, and neither may enter the other's home (issue #221).
- ES: el suelo de `rich` sube de `>=13.8` a `>=14.2` (mismo tope `<16`). Es la consecuencia aritmética de adoptar `textual`, que exige `rich>=14.2.0`: por debajo de eso el árbol de dependencias ya no resuelve, así que el `13.8` habría pasado a ser una ficción en el archivo. Queda escrito como adenda 2 del ADR 0027, que era donde faltaba decirlo (issue #221).
- EN: the `rich` floor rises from `>=13.8` to `>=14.2` (same `<16` cap). It is the arithmetic consequence of adopting `textual`, which requires `rich>=14.2.0`: below that the dependency tree no longer resolves, so `13.8` would have become a fiction in the file. Written down as addendum 2 of ADR 0027, which is where it was missing (issue #221).
- ES: la capa de salida gana `interactive_ui_blocker()` / `interactive_ui_enabled()`, la puerta que decide si puede arrancar una aplicación de pantalla completa. Vive donde vive el resto de la detección de terminal del proyecto, devuelve un valor y **no construye nada**: no importa `textual` y no lo hará. Hace falta que la puerta sea nuestra porque, medido sobre `textual` 8.2.8, la librería no mira `TERM=dumb` en ningún sitio y no se niega a arrancar sin TTY (issue #221).
- EN: the output layer gains `interactive_ui_blocker()` / `interactive_ui_enabled()`, the gate that decides whether a full-screen application may start. It lives where the rest of this project's terminal detection lives, returns a value and **builds nothing**: it does not import `textual` and never will. The gate has to be ours because, measured on `textual` 8.2.8, the library checks `TERM=dumb` nowhere and does not refuse to start without a TTY (issue #221).
- ES: la validación de modo, nivel de seguridad y puerto pasa a `nz_mcp/wizard/fields.py` y la usan **los dos caminos**. No hay una segunda implementación de nada: la pantalla recoge el borrador y llama a las mismas funciones de siempre para la escalera de tres niveles, para las cuatro salidas ante un fallo y para escribir el perfil. Los resultados de la validación se siguen imprimiendo por `cli_output` en la terminal normal **al salir de la pantalla**, para que lo que se pega en un issue siga siendo la salida de siempre (issue #221).
- EN: mode, security level and port validation move to `nz_mcp/wizard/fields.py` and **both paths** use them. There is no second implementation of anything: the screen collects the draft and calls the same functions as always for the three-level ladder, for the four ways out of a failure and for writing the profile. Validation results are still printed by `cli_output` on the ordinary terminal **after the screen closes**, so what gets pasted into an issue is still the output it always was (issue #221).
- ES: **cambio observable** — la ayuda (`nz-mcp`, `nz-mcp --help`) se reescribe entera. Los once comandos dejan de salir en orden de registro —`version` primero, `init` segundo— y salen en el **orden en que se usan**: `init`, `test-connection`, `list-profiles`, `switch-profile`, `add-profile`, `edit-profile`, `remove-profile`, `doctor`, `probe-catalog`, `version` y `serve`. La cabecera nombra por dónde empezar (*"Si acabas de instalarlo, empieza por: nz-mcp init"*), que antes no lo decía nadie. Y las descripciones dicen para qué sirve cada comando sin nombrar tools MCP (`switch-profile` decía *"same logic as the nz_switch_profile tool"*), sin archivos internos y sin las marcas de reStructuredText que `test-connection` imprimía literales (issue #209).
- EN: **observable change** — the help screen (`nz-mcp`, `nz-mcp --help`) is rewritten. The eleven commands no longer come out in registration order — `version` first, `init` second — but in **the order you use them**: `init`, `test-connection`, `list-profiles`, `switch-profile`, `add-profile`, `edit-profile`, `remove-profile`, `doctor`, `probe-catalog`, `version` and `serve`. The header names where to start (*"If you just installed it, start with: nz-mcp init"*), which nothing used to say. And each description says what the command is for, without naming MCP tools (`switch-profile` used to say *"same logic as the nz_switch_profile tool"*), without internal file names, and without the reStructuredText markup `test-connection` printed literally (issue #209).
- ES: **cambio observable** — la ayuda pasa a hablar el idioma configurado. Con `NZ_MCP_LANG=es` sale en español, títulos de comandos y opciones incluidos; antes salía siempre en inglés porque venía de los docstrings, que por la regla del proyecto van en inglés y no pasan por el catálogo i18n. Quedaba una pantalla mezclada: ayuda en inglés y, dos minutos después, un asistente que preguntaba en español. Se traducen las descripciones y las opciones; **no** se traducen los nombres de los comandos, los códigos de error ni el JSON de `--json` (issues #209, #169).
- EN: **observable change** — the help screen now speaks the configured language. With `NZ_MCP_LANG=es` it comes out in Spanish, command and option descriptions included; it used to be English always because the text came from the docstrings, which are English by project rule and never reach the i18n catalog. The result was a mixed screen: English help, and two minutes later a wizard asking questions in Spanish. Descriptions and options are translated; command names, error codes and the `--json` document are **not** (issues #209, #169).
- ES: los textos de la ayuda se escriben con caracteres que una consola de Windows con página de códigos heredada (cp437 / cp850) sabe dibujar. La raya larga de la línea de `doctor` salía como `keyring ? no Netezza` en una consola recién instalada; las vocales acentuadas minúsculas, la eñe y la apertura de interrogación sí están en esas páginas y se usan con normalidad. Hay test que lo comprueba clave a clave, en los dos idiomas (issue #209).
- EN: help texts are written with characters a Windows console on a legacy code page (cp437 / cp850) can actually draw. The em dash on the `doctor` line used to render as `keyring ? no Netezza` on a stock console; lowercase accented vowels and Spanish punctuation are present in those code pages and are used normally. A test checks it key by key, in both languages (issue #209).
- ES: **cambio observable** — `nz-mcp list-profiles` deja de imprimir solo nombres. Con **dos o más** perfiles muestra una tabla con perfil, host, base de datos, modo y una marca `*` en el activo, que es lo que hace falta para saber a dónde apunta lo que estás a punto de dejar en manos de un asistente. Con **uno solo** no dibuja tabla: una fila no se compara con nada, así que sale como `clave: valor`. Y sin ninguno, dice cómo crear el primero en vez de un paréntesis vacío. **Cambia el formato de stdout**: quien tuviera un script leyendo un nombre por línea tiene que ajustarlo (issue #169).
- EN: **observable change** — `nz-mcp list-profiles` no longer prints bare names. With **two or more** profiles it shows a table with profile, host, database, mode and a `*` on the active one, which is what you need to know where the thing you are about to hand an assistant is pointing. With **one** it draws no table: a single row has nothing to compare itself against, so it comes out as `key: value`. With none, it says how to create the first one instead of printing an empty parenthesis. **The stdout format changes**: a script reading one name per line needs adjusting (issue #169).
- ES: la marca del perfil activo usa la **misma regla que el servidor** para decidir cuál lo es (campo `active`, después `NZ_MCP_PROFILE`, y por último el único perfil si solo hay uno). Antes esa regla vivía únicamente dentro de `get_active_profile`; ahora está en un sitio y la usan los dos, porque dos respuestas distintas a "qué perfil se está usando" es una de más.
- EN: the active marker uses **the same rule as the server** to decide which profile is active (the `active` field, then `NZ_MCP_PROFILE`, then the only profile when there is just one). That rule used to live inside `get_active_profile` alone; now it lives in one place and both use it, because two different answers to "which profile is in use" is one too many.
- ES: `nz-mcp edit-profile` y `nz-mcp test-connection` dejan de mezclar idiomas. Sus mensajes estaban escritos en inglés dentro del código: `Invalid --mode`, `No changes`, `Updated profile`, y los prefijos `OK:`, `FAIL:` y `HINT:`, este último seguido de un hint que sí estaba traducido. El resultado era una pantalla que decía `OK: connected to ... as ...` y justo debajo `HINT: revisa el host...`. Ahora todos pasan por el catálogo ES/EN, y el de `--mode` explica qué significa cada modo en vez de listar tres palabras (issue #169).
- EN: `nz-mcp edit-profile` and `nz-mcp test-connection` stop mixing languages. Their messages were hardcoded English — `Invalid --mode`, `No changes`, `Updated profile`, and the `OK:`, `FAIL:` and `HINT:` prefixes, the last one followed by a hint that *was* translated. The screen ended up saying `OK: connected to ... as ...` and right below it `HINT: revisa el host...`. All of them now come from the ES/EN catalog, and the `--mode` one explains what each mode means instead of listing three words (issue #169).
- ES: **cambio observable** — `nz-mcp probe-catalog` deja de esperar en silencio y deja de enterrar lo que importa. Mientras corre, un **indicador con contador** en stderr dice qué consulta está en marcha (`[########------------] 7/14 consultando table_stats`); es el único sitio del CLI donde un porcentaje es honesto, porque el total de consultas se conoce de antemano y no se lo inventa nadie. El indicador se anuncia **antes** de lanzar cada consulta, no después: así, cuando una se atasca, la pantalla dice en cuál. Al terminar se borra solo (issue #206).
- EN: **observable change** — `nz-mcp probe-catalog` no longer waits in silence, and no longer buries what matters. While it runs, a **determinate indicator** on stderr names the query in flight (`[########------------] 7/14 running table_stats`); it is the one place in this CLI where a percentage is honest, because the number of queries is known in advance rather than invented. The indicator is drawn **before** each query rather than after: when one hangs, the screen says which. It erases itself at the end (issue #206).
- ES: **cambio observable** — el informe por defecto ya no imprime las catorce líneas. Salen primero los `[FAIL]`, después los `[WARN]`, y se cierra con una frase (*"11 de 14 consultas OK: 1 con fallo, 2 sin validar"*) y **un** siguiente paso. Las consultas que funcionan no se listan: once líneas `[OK]` eran justo lo que dejaba un fallo escondido en medio. Para verlas todas hay una bandera nueva, `--verbose`, que las presenta en tabla con consulta, estado, milisegundos y filas (issue #206).
- EN: **observable change** — the default report no longer prints all fourteen lines. `[FAIL]` entries come first, then `[WARN]`, and it closes with one sentence (*"11 of 14 queries OK: 1 failed, 2 not validated"*) and **one** next step. Queries that worked are not listed: eleven `[OK]` lines were exactly what hid a failure in the middle of them. A new `--verbose` flag shows them all, in a table with query, status, milliseconds and rows (issue #206).
- ES: el informe legible sale **entero por stderr**, un solo flujo, y stdout sigue siendo exclusivo de `--json`, que **no cambia ni un byte**. Redirigir stderr a un archivo (`nz-mcp probe-catalog 2> informe.txt`) da el informe completo y limpio: sin indicador, sin retornos de carro y sin secuencias de escape, porque sin terminal el indicador no escribe absolutamente nada. Hay test en subproceso que lo fija.
- EN: the readable report goes to **stderr in full**, as a single stream, and stdout stays exclusive to `--json`, which is **byte-for-byte unchanged**. Redirecting stderr to a file (`nz-mcp probe-catalog 2> report.txt`) yields the complete, clean report: no indicator, no carriage returns, no escape sequences, because without a terminal the indicator writes nothing at all. A subprocess test pins it.
- ES: **cambio observable** — el CLI reparte su salida en dos canales y ya no improvisa el canal en cada línea. Por **stdout** sale solo el contenido que un script canaliza o redirige: la versión, los nombres de `list-profiles`, el informe de `doctor`, los documentos `--json` y el bloque de `claude_desktop_config.json`. Todo lo que lee una persona —confirmaciones, avisos, errores, las preguntas del asistente, la escalera de validación y el informe de `probe-catalog`— pasa a **stderr**. **Ningún texto cambia**: cambia por dónde sale. Motivo: `nz-mcp serve` habla JSON-RPC por stdout y un solo byte de más rompe el cliente MCP; hasta ahora eso dependía de que nadie añadiera un `typer.echo` en ese camino, y había 58 llamadas directas a `typer.echo` / `typer.secho` repartidas por `cli.py`, todas con stdout por defecto. Quien encadene comandos en scripts nota la diferencia: `nz-mcp list-profiles > perfiles.txt` deja el archivo con los nombres y nada más, y `nz-mcp probe-catalog` sin `--json` deja stdout vacío —su superficie de máquina es `--json`— (issue #203).
- EN: **observable change** — the CLI now splits its output in two channels instead of picking one per line. **stdout** carries only what a script pipes or redirects: the version, the `list-profiles` names, the `doctor` report, `--json` documents and the `claude_desktop_config.json` block. Everything a person reads — confirmations, warnings, errors, the wizard questions, the validation ladder and the `probe-catalog` report — moves to **stderr**. **No message text changes**: only the channel does. Reason: `nz-mcp serve` speaks JSON-RPC over stdout and one extra byte breaks the MCP client; until now that held only because nobody had added a `typer.echo` on that path, and `cli.py` had 58 direct `typer.echo` / `typer.secho` calls, all defaulting to stdout. Anyone scripting around the CLI will notice: `nz-mcp list-profiles > profiles.txt` leaves the names and nothing else, and `nz-mcp probe-catalog` without `--json` leaves stdout empty — its machine surface is `--json` (issue #203).
- ES: `rich` pasa a estar **declarado** como dependencia directa y **acotado** a `rich>=13.8,<16` (ADR 0027). No se instala nada nuevo: `typer>=0.15` ya exigía `rich>=13.8.0` de forma dura, así que toda instalación de nz-mcp lo traía dentro; lo que cambia es que el suelo y el tope los fija este proyecto y no un tercero. Un `pip install nz-mcp` deja de poder resolver un `rich` de un major que nadie ha revisado, que es la lección de los PR #163 y #187 (issue #204).
- EN: `rich` is now a **declared** direct dependency, **bounded** to `rich>=13.8,<16` (ADR 0027). Nothing new gets installed: `typer>=0.15` already hard-required `rich>=13.8.0`, so every nz-mcp install already shipped it; what changes is that the floor and the cap belong to this project instead of a third party. `pip install nz-mcp` can no longer resolve a `rich` major nobody has reviewed — the lesson of PR #163 and #187 (issue #204).

### Fixed
- ES: **cambio observable** — el bloque de `claude_desktop_config.json` que imprime el asistente ya lleva la **ruta absoluta real** del ejecutable. Antes imprimía `"command": "nz-mcp"` a secas, justo lo que la documentación desaconseja con todas las letras: Claude Desktop no arranca con el `PATH` de tu terminal, así que el servidor no arrancaba y el único rastro quedaba en `mcp-server-netezza.log`, tres capas más abajo. El fallo era silencioso y diferido, y ocurría en el último paso de la instalación, cuando ya habías hecho todo bien. La ruta se resuelve en tiempo de ejecución mirando primero el directorio de scripts de la instalación que está corriendo —lo que cubre pipx y los entornos virtuales en Windows, macOS y Linux, incluido `pip install --user`— y solo después el `PATH`, porque un `nz-mcp` global puede ser otro distinto. En Windows las barras invertidas van escapadas por `json.dumps`, de modo que el bloque es JSON válido y se pega tal cual (issue #207).
- EN: **observable change** — the `claude_desktop_config.json` block printed by the wizard now carries the **real absolute path** of the executable. It used to print a bare `"command": "nz-mcp"`, exactly what the documentation warns against in plain words: Claude Desktop does not start with your terminal `PATH`, so the server never started and the only trace was in `mcp-server-netezza.log`, three layers down. The failure was silent and deferred, and it happened on the last step of the install, when you had already done everything right. The path is resolved at runtime by looking first at the scripts directory of the installation that is running — which covers pipx and virtual environments on Windows, macOS and Linux, including `pip install --user` — and only then at `PATH`, because a global `nz-mcp` may be a different one. On Windows the backslashes are escaped by `json.dumps`, so the block is valid JSON and can be pasted as printed (issue #207).
- ES: si la ruta **no** se puede determinar, el asistente no se la inventa: `command` lleva un marcador evidente (`<ruta absoluta de nz-mcp>`) y debajo aparece el comando que la imprime, `where.exe nz-mcp` en Windows y `which nz-mcp` en el resto, con el recordatorio de por qué hace falta. Un marcador que salta a la vista cuesta menos que un valor plausible que falla en silencio (issue #207).
- EN: when the path **cannot** be determined the wizard does not invent one: `command` carries an obvious placeholder (`<absolute path to nz-mcp>`) and below it the command that prints the real one, `where.exe nz-mcp` on Windows and `which nz-mcp` elsewhere, plus the reminder of why it is needed. A placeholder that jumps out costs less than a plausible value that fails silently (issue #207).

### Added
- ES: la capa de salida gana `table()`, que alinea columnas y **devuelve texto** en vez de escribir: quien llama decide el canal.
